    Docs & Help

    Everything you need to know to get value out of this tool — from your first paste to managing a multi-feature project. Skim the table of contents on the left, or read top-to-bottom.

    What is this?

    When you build a Flutter app that talks to a backend, the backend sends data as JSON. To use that data in Dart you need a model class — a Dart class that mirrors the JSON shape and knows how to parse itself.

    Writing those classes by hand is slow and error-prone, especially when responses have nested objects and arrays. This tool reads any JSON and writes the Dart class for you — and it does it the way an experienced Flutter developer would.

    It doesn't just convert types. It also:

    • Names classes and folders the way real Flutter teams structure their code.
    • Adds defensive parsing (so dirty server data doesn't crash your app).
    • Distinguishes response models (data you receive) from param models (data you send).
    • Bundles a helper utility so generated code works in any Flutter project with zero extra dependencies.
    • Lets you save multiple generated models into a "project" and download the whole thing as a ready-to-drop folder.
    • Auto-fixes incomplete JSON pastes (missing braces, trailing commas, JS-style comments).

    Why use it?

    If you've used the original json_to_dart before, you may have run into these problems. This tool fixes them:

    Problem in the originalWhat this tool does
    null values become Null? (a useless type) They become dynamic so you can store any value later.
    [] (empty list) becomes List<Null>? Becomes List<dynamic>? — usable.
    toJson() always sends null keys to the server Optional null-check wrapping — empty fields are omitted.
    If the server sends "12" instead of 12, fromJson crashes Optional ConvertService wraps every parse call so type mismatches never throw.
    Output is one giant file with all classes mashed together Output is a clean folder structure — one class per file, organized by nesting depth.
    No way to manage multiple generations Built-in Projects workspace saves multiple JSON pastes per app.
    No documentation export One click exports markdown docs for any model or whole project.
    JSON must be 100% valid before pasting Auto-fixes common paste mistakes — trailing commas, missing braces, JS-style comments.

    Quick example

    Paste this JSON:

    {
  "id": 12,
  "name": "Home",
  "menu": [
    {
      "title": "Profile",
      "sub_menu": [{ "title": "Account" }]
    }
  ],
  "user": { "id": 1, "name": "Alex", "avatar": null }
}

    You get this folder structure:

    api_home/
├── api_home_model.dart       (ApiHomeModel)
├── user_model.dart           (UserModel — flat, no nested objects)
└── menu/
    ├── menu_model.dart       (MenuModel — has its own folder, contains sub_menu)
    └── sub_menu_model.dart   (SubMenuModel)

    And this is what api_home_model.dart contains:

    import 'package:my_app/api_home/menu/menu_model.dart';
import 'package:my_app/api_home/user_model.dart';

class ApiHomeModel {
  int? id;
  String? name;
  List<MenuModel>? menu;
  UserModel? user;

  ApiHomeModel({this.id, this.name, this.menu, this.user});

  ApiHomeModel.fromJson(Map<String, dynamic> json) {
    id = json['id'];
    name = json['name'];
    if (json['menu'] != null) {
      menu = <MenuModel>[];
      json['menu'].forEach((v) {
        menu!.add(MenuModel.fromJson(v));
      });
    }
    if (json['user'] != null) {
      user = UserModel.fromJson(json['user']);
    }
  }

  Map<String, dynamic> toJson() { /* ... */ }
}
    This is exactly what an experienced Flutter developer would write by hand. No magical annotations, no codegen step — just plain Dart you can edit.

    How to use it (step by step)

    1. Pick a naming style

    The first card on the left asks: API model or Param model?

    • API model — pick this when the JSON is something you received from the server (a response). The root class is named Api<Name>Model.
    • Param model — pick this when the JSON is something you'll send to the server (a request body). The root class is named Pm<Name>Model.

    This naming is a convention used by Flutter teams to make the role of each class obvious at a glance.

    2. Type a "root name"

    This is the name of the screen, feature, or endpoint the JSON belongs to:

    • For the home page response → home
    • For the login request body → login
    • For a list of products → products

    The tool combines this with the mode prefix to name the root class and folder. You'll see a live preview right under the input.

    3. (Optional) Set a "package name"

    If you know your Flutter app's package name (the value after name: in pubspec.yaml, like my_app), type it here. The tool will produce absolute imports: 

    import 'package:my_app/api_home/menu/menu_model.dart';

    If left blank, you get relative imports:

    import 'menu/menu_model.dart';

    Both work in Flutter; absolute imports are slightly more readable in big apps.

    4. Paste your JSON

    Big text area in the middle. Copy a real API response (or request body) and paste it. Don't worry about minor formatting issues — the tool auto-fixes most paste mistakes (see JSON auto-fix).

    Tip: click Load sample to see the tool in action with example JSON.

    5. Pick options

    The right sidebar has checkboxes for helpers and capabilities. Sensible defaults are pre-selected. See Every option, explained below.

    6. Click Generate ▸

    The right pane fills with one tab per generated class. Click any tab to view its content with syntax highlighting.

    7. Copy or download

    • Copy active — copies the currently visible file to your clipboard.
    • Download .zip — packages all files (with their folder structure) into a ZIP. If you enabled ConvertService, the helper file is included too.
    • Download convert_service.dart only — grab just the helper standalone, useful for adding it to an existing project.
    • Download docs — exports markdown documentation, great for handing context to teammates or AI assistants.
    • Save to Project — adds these files to a saved project (see Projects feature).

    Every option, explained

    "Use ConvertService in fromJson"

    When off (default), parsing looks like:

    id = json['id'];

    This crashes if the server sends the field as the wrong type (e.g. a string "12" when you expect an int).

    When on, parsing looks like:

    id = ConvertService.convertInt(json['id']);

    The ConvertService helper coerces values safely. If parsing fails, you get 0 or "" or false instead of an exception.

    Recommended for any production app. A real backend will eventually send unexpected types, and this prevents the entire screen from crashing. When you enable this, the downloaded ZIP automatically includes utils/convert_service.dart.

    "Wrap each toJson field in a null check"

    Without this, every field is sent to the server even if it's null:

    data['contract_start_date'] = contractStartDate;  // sends null

    With this enabled:

    if (contractStartDate != null) {
  data['contract_start_date'] = contractStartDate;
}

    Auto-enabled when you pick Param mode — request bodies almost always want this. Some APIs reject null values, and many ignore them but waste bandwidth.

    Capabilities

    These add static helper methods inside each generated class. They're optional — turn them on if you find them useful, off if you want minimal output.

    parseItem(json)

    Parses one object safely:

    final user = UserModel.parseItem(apiResponse.data);

    If the input isn't an object, it returns an empty UserModel() instead of throwing.

    parseItems(json)

    Parses a list of objects, handling two common API shapes:

    // shape 1: raw list
final list = UserModel.parseItems([{...}, {...}]);

// shape 2: wrapped under "data"
final list = UserModel.parseItems({ "data": [{...}, {...}] });

    Both work without you needing to check the shape first.

    copyItem(source) / copyItems(list)

    Deep-copies an object (or a list of them). Useful when you want to edit a copy without mutating the original:

    final clone = UserModel.copyItem(original);
clone.name = "New name";  // doesn't affect original

    toString() override

    Replaces Dart's default Instance of 'UserModel' with something readable:

    print(user); // prints "Alice" instead of "Instance of 'UserModel'"

    The tool picks the most-likely-friendly field automatically: name, title, label, id, or the first string field.

    Use cases

    1. Starting a new Flutter screen

    You got an API contract from the backend team — a sample JSON response. Paste it here, generate the model, drop it into your lib/features/<screen>/models/ folder, and start writing UI immediately.

    2. Building a request body model

    You need to call POST /login with { email, password, device_id }. Paste a sample body, switch to Param mode, generate PmLoginModel. The toJson() is null-safe by default, so optional fields aren't sent when empty.

    3. Migrating a legacy app

    Your app has hand-written models that crash on null fields. Paste a real API response, enable ConvertService, generate, and replace the old model. The new one survives any kind of dirty data.

    4. Building multiple features at once

    Use the Projects tab. Create a project for the app you're building. Each time you generate a model, click Save to Project with a feature name (e.g. audit, profile). When you're done, hit Download project ZIP and you get a ready-to-extract lib/features/... tree.

    5. Documenting an API for your team

    Generate models from each endpoint. Use Download docs — you get a markdown bundle showing every field, type, and the original sample JSON. Drop it in your repo wiki or share it with new joiners.

    6. Feeding context to an AI assistant

    The markdown docs are formatted for readability. Paste them into ChatGPT/Claude/Cursor when asking for help with API integration — the assistant gets the full schema in seconds.

    What you get out

    For a JSON with nested objects and lists, with API mode + all options on, you get something like this:

    api_home/
├── api_home_model.dart       <- root class (ApiHomeModel)
├── user_model.dart           <- UserModel (no nested objects → flat file)
└── menu/                     <- menu has nested sub_menu → its own folder
    ├── menu_model.dart       <- MenuModel
    └── sub_menu_model.dart   <- SubMenuModel
utils/
└── convert_service.dart      <- helper, only if ConvertService option is on

    The folder rule (simple)

    • A class with no nested objects lives as a flat file in its parent folder.
    • A class with nested objects gets its own subfolder.
    • The root class always gets its own folder named api_<root> or pm_<root>.

    This keeps deep models from cluttering one giant folder.

    Type inference rules

    JSONDart
    nulldynamic (NOT Null?)
    [] or all-null listList<dynamic>?
    Mixed-type listList<dynamic>?
    [1, 2.0]List<double>? (int+double promote)
    Whole numberint?
    Fractional numberdouble?
    StringString?
    Booleanbool?
    ObjectGenerated <Name>Model?
    Array of objectsList<<Name>Model>? (fields merged across all elements)

    JSON auto-fix

    The tool tries to be forgiving with paste mistakes. The following fixes are applied automatically when you click Generate or Format:

    1. Wraps a stray key-value fragment in { ... }

    You can paste just an inner property like:

    "taskteam_time_record": {
  "id": 521,
  "user_id": "22293"
},

    The tool wraps it for you:

    {
  "taskteam_time_record": {
    "id": 521,
    "user_id": "22293"
  }
}

    2. Wraps multiple objects in [ ... ]

    If you paste two-or-more comma-separated objects without enclosing brackets, it auto-wraps them as an array.

    3. Strips trailing commas

    { "a": 1, } → { "a": 1 }. Required by JSON, but JS object literals allow them — easy mistake.

    4. Strips JS-style comments

    Both // line and /* block */ comments are removed before parsing. Useful when copying from a JS file or annotated example.

    The status line under the input shows what was fixed, e.g. "auto-fixed: removed trailing comma, wrapped in {{ ... }}".

    The Format button

    Click the Format link in the input toolbar to apply the same auto-fixes and pretty-print the result, without generating. Useful for previewing what the tool will work with.

    Projects feature

    The Projects tab lets you accumulate multiple generated model sets into one workspace.

    How it works

    1. Click + New in the Projects tab.
    2. Give it a name (e.g. the name of your Flutter app).
    3. Go back to Generator, paste JSON, generate.
    4. Click Save to Project — pick the project, give it a "feature name" (e.g. audit, profile).
    5. Repeat for every endpoint.

    When you're ready, open the project and click Download project ZIP. You get this layout:

    my-app/
├── lib/
│   ├── features/
│   │   ├── audit/
│   │   │   └── models/
│   │   │       ├── api_audit_list/
│   │   │       └── pm_audit_filter/
│   │   ├── profile/
│   │   │   └── models/
│   │   └── dashboard/
│   │       └── models/
│   └── core/
│       └── utils/
│           └── convert_service.dart   (only if any saved model uses it)
└── README.md

    This matches the standard Flutter "feature-first" folder layout.

    Where projects live

    In your browser's localStorage. They never leave your device. No server, no signup. If you clear your browser data, projects are gone — so download ZIPs of important work.

    ConvertService helper

    The bundled convert_service.dart is a small Dart class with defensive type-conversion helpers. Every method:

    • Accepts any input type
    • Returns a sensible default (0, "", false, null, []) on failure
    • Never throws an exception

    Available helpers

    MethodPurpose
    convertString(data)Returns string, "" on null
    convertStringNullable(data)Returns string or null
    convertInt(data)Coerces to int, 0 on failure
    convertIntNullable(data)Coerces to int or null
    convertNum(data)Coerces to num
    convertDouble(data)Coerces to double, 0 on failure
    convertDoubleNullable(data)Coerces to double or null
    convertDoubleRound(data, fractionDigits: 2)Coerces and rounds
    convertBool(data)Handles "true"/"1"/"yes"/true
    convertBoolInt(data)Treats "1" as true (0/1 APIs)
    convertDateTime(data)Parses ISO date strings
    convertMap(data)Returns Map<String, dynamic> (parses JSON string if given)
    parseStringList(data)List of strings
    parseIntList(data)List of ints (decodes JSON string if given)
    parseDoubleList(data)List of doubles
    parseNumList(data)List of nums
    parseBoolList(data)List of bools
    parseList<T>(data, fromJson)Generic list of any model class

    Get just the helper file

    If you want only convert_service.dart (e.g. to drop into an existing project without changing the rest of your code), click Download convert_service.dart only in the sidebar — no JSON input needed.

    Docs export

    Two flavors of exported documentation:

    Per-generation docs (Generator → "Download docs")

    Bundles markdown files describing the current generation:

    • A README.md index listing every class
    • One .md per class with field table (name, JSON key, Dart type), the original sample JSON, and the generated Dart for reference

    Same idea, but for every model set saved in the project. Useful for handover, code review, or onboarding.

    FAQ

    Is my JSON sent anywhere?

    No. Everything runs in your browser. There's no backend. You can verify by opening the tool, switching to airplane mode, and confirming generation still works.

    Can I use this for sensitive / production data?

    You can, with the same caveat as any browser tool: pasting real production JSON into a webpage means trusting that webpage's code. Since this tool is open source and runs entirely client-side, you can audit it. For maximum safety, run it locally — see the GitHub README for instructions.

    Does this generate freezed / json_serializable classes?

    No, by design. The output is plain Dart with manual fromJson / toJson. Reasons:

    • Zero dependencies — works in any Flutter project as-is
    • No build step required
    • Readable — you can edit the generated class without re-running a code generator

    If you specifically want freezed / json_serializable, use those packages directly.

    What if my JSON has a list with mixed types?

    Mixed-type lists (e.g. [1, "two", true]) become List<dynamic>?. The tool can't infer a single type when there isn't one. You can refine to a more specific type by editing the generated class.

    Two of my fields produce the same class name. What happens?

    The tool currently produces one shared class for both. Workaround: rename one of the JSON keys before pasting, or rename the generated class manually. Automatic name-collision handling is on the roadmap.

    Will my saved projects sync across devices?

    No — they're stored in your browser's localStorage, which is per-device-per-browser. To move a project, download the project ZIP and re-import on the other device (manual for now).

    Can I edit a saved model set?

    Not yet — saved sets are read-only snapshots. To "edit", regenerate from the source JSON and save again with a new feature name (or delete the old one first).

    Why two different "Model" suffixes?

    The root class always gets a prefix (Api or Pm) so its role is obvious. Nested classes don't need it — MenuModel inside ApiHomeModel is clearly a sub-piece of an API response. This keeps names concise.

    Troubleshooting

    "Invalid JSON" but my JSON looks fine

    Most common causes (and the auto-fix already handles most):

    • Missing the outer { } — auto-fixed.
    • Trailing commas ({ "a": 1, }) — auto-fixed.
    • Single quotes instead of double quotes — NOT auto-fixed (too risky, could break strings with apostrophes). Use find-and-replace in your text editor first.
    • Unquoted keys ({ id: 1 } instead of { "id": 1 }) — NOT auto-fixed. Use a JSON formatter to clean up.

    Generated nothing happens after clicking Generate

    • Open the browser console (Cmd/Ctrl + Option + I) and look for red errors.
    • Make sure the input area isn't empty.
    • Try Load sample first — if that works, it's something specific to your JSON.

    The download didn't start

    Some browsers block scripted downloads if you haven't interacted with the page recently. Click anywhere in the page and try the download button again.

    I lost my projects

    Projects live in your browser's localStorage. Common causes of disappearance:

    • You cleared "Site Data" / "Cookies" for the page.
    • You're using Incognito/Private mode (localStorage is cleared on tab close).
    • Browser settings auto-clear local storage on quit.

    Defence: download project ZIPs regularly. They're the only durable copy.
